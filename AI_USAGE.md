# AI usage

## Tool

Claude Code (Anthropic's coding assistant) was used throughout development: planning, code, tests and documentation. The running application calls no language model, hosted or local.

## How it was used

- The work was split into seven phases (`PLAN.md`), one session per phase. Each session ended with the tests passing, a commit, and the decisions of that phase added to `DECISIONS.md` with the reason for each.
- Most code and tests were generated by the assistant from that plan and then reviewed. The design decisions are mine to defend; `DECISIONS.md` is the record I use for that.

## What was reviewed and changed

- **MCP SDK API.** Most published examples use the v1 `FastMCP` names. The installed SDK is v2 (2.3.0), so the server and client API was checked against the installed package with a stdio spike on Windows before any server code was written.
- **Read-only access.** Checked that the MCP server's connection really rejects writes (`mode=ro` plus `PRAGMA query_only`), with a test that UPDATE, DELETE and CREATE fail and a missing database file is not created.
- **MCP Inspector.** Ran the Inspector against the server, listed tools and resources and called read operations. It showed the tools advertised as possibly destructive (the SDK default), which led to adding read-only annotations.
- **Threshold.** The first value (0.15) was read off a handful of fixture scores. The evaluation sweep showed it sat 0.0001 below a wrong match, so it was moved to 0.17.
- **Out-of-vocabulary scoring.** The evaluation found a false accept: a short off-topic question passed on one shared word because scikit-learn drops unseen words. Retrieval was changed so unseen query words count against the score. The first version of that fix used the textbook weight and broke a real ticket's draft (T-104), so it was changed to a milder weight.
- **Composer.** Reviewed sentence selection against the two cases where cutting or reordering sentences would invert the guidance (KB-01 pending payment, KB-06 disclaimer).

## What was tested

- 134 backend tests and 2 frontend tests, run after every phase.
- The 10 supplied expected cases (`tests/test_expected_cases.py`).
- A grounding checker that compares every quoted line in every answer with the database rather than with the answer's own citations, plus tamper tests proving the checker fails when a claim is added, a sentence is shortened or a citation is invented.
- All five actions and the empty, insufficient-evidence, validation and reviewed states live in the browser.
- A cold start from a fresh clone following the README: install, seed, tests, API, frontend, and each action through the frontend proxy, with `uv` in offline mode after install.

## Not verified

- The 503 state in the UI was not triggered in the browser; it is covered by the API test and the error mapping only.
- The cold start was run with package tools offline, not with the machine's network physically disconnected.
